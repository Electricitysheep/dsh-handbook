# README 信息架构评审

> 评审对象：`README.md`（264 行，16 个二级区块）· 评审视角：首次访问读者

## 发现的 5 个问题

### 1. 首屏被"介绍"占满，没有行动入口
标题之后依次堆叠：3 行引言（tagline + Star 求星 + 语言切换）→ 720px banner → 5 枚徽章。
读者第一屏看到的全是"这是什么"的自我描述，**没有任何可立即执行的动作**；且 Star 求星出现在读者还没读任何内容之前，说服力最弱的时刻。

### 2. 关键卖点埋没在底部
- "30 秒快速体验"排在第 4 位（L41）——最有行动价值的内容太靠后；
- "为什么值得读（而不是只看官方文档）"这个**最强差异化卖点**沉到 L237（排在 benchmark、PDF 之后），对比表完全失去第一眼说服力。

### 3. 内容重复
- headless 命令 `dsh --profile headless "你好，请用一句话介绍自己"` 在"快速体验"（L49）和"演示 ②"（L185）出现两次；
- "为什么值得读"表格与"这是什么"段落语义重复——两处都在讲"官方文档以架构为主、缺上手路径"；
- "内容精华速览"的要点与"目录"表第三列"你将学会"高度重叠（保留可接受，但顺序必须修）。

### 4. 顺序错误
"内容精华速览"中**第 7 章详情块排在附录之后**（L164-170），整个速览的阅读顺序变成 1,2,3,4,5,6,8,9,10,附录,7，破坏"从 0 到 1"的顺序感。

### 5. 数据不一致与渲染错误
- 第 1 章速览写 **"vs 6 个主流 Agent"但只列了 5 个名字**（Claude Code/Codex/OpenCode/Gemini/Kimi）；对照 `docs/01-intro.md` 实际是"核心六家"= dsh + 5 家；
- 能力矩阵"自动化/CI"和"TUI"两行**各缺一列**（Kimi 缺失，`docs/01-intro.md` 中两格均为 ✅），GitHub 表格渲染错位；
- 4 处 `<b>...</strong>` 标签不配对（L103/112/120/165），HTML 不规范。

## 附加观察
16 个二级标题全部无 emoji 分区，GitHub 长页面上难以快速定位区块（扫描性弱）。
